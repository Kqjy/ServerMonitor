# Collectors

One `*.go` per metric family. `Register()` in an `init()` adds a collector to the global registry; implement `Name()`, `Platforms()`, `Collect(ctx)`, and optionally the `ProcessCollector` / `ContainerCollector` interfaces.

Per-platform availability is declared by each collector's `Platforms()` and by build-tag filename suffixes (`_linux.go`, `_windows.go`, `_nonwindows.go`).

## SMART capabilities on Linux

On Linux, `--enable-smart` grants `CAP_SYS_RAWIO`, which covers SATA/SAS SMART (SG_IO ioctl) only. **NVMe SMART reads (`NVME_IOCTL_ADMIN_CMD`) are gated by the kernel behind `CAP_SYS_ADMIN`** regardless of file/group permissions, so NVMe-only hosts collect no SMART data under `--enable-smart` alone. Use `--enable-smart-nvme` (`SM_ENABLE_SMART_NVME=1`) to additionally grant `CAP_SYS_ADMIN` — near-root, so it is a separate opt-in and is **not** included in `--enable-all`. When devices are scanned but their reads fail, the collector reports `read_failed` (DiskTab surfaces an NVMe/`CAP_SYS_ADMIN` banner). On Windows, NVMe SMART works under the Admin service (LocalSystem) with a recent smartmontools and needs no extra capability.

## Hardware RAID

A RAID virtual disk (MegaRAID/PERC/SMC, HP Smart Array, Adaptec, 3ware, Areca) scans as a plain SCSI device with no SMART of its own, so the collector runs async passthrough discovery: any scanned SCSI device whose `smartctl -i` identity reports no SMART support is probed with `-d megaraid,N` / `cciss,N` / `aacraid,0,0,N` / `3ware,N` (on `/dev/tw?0`) / `areca,N`, walking device IDs with a miss-streak cutoff (MegaRAID IDs often start at 8). Members are deduped by serial (two virtual disks on one controller expose the same drives), labeled `sda#8`-style plus a `model` label, and the virtual disk is hidden once members are found. A controller detected with zero reachable members reports state `raid_unreadable` (DiskTab banner). Discovery runs as a background goroutine outside the tick budget and is re-run every device-cache TTL (5m). Per-device reads run in a 4-worker background sampler every 300s by default, configurable with `smart_sample_s` or `SM_SMART_SAMPLE_S` from 60s to 3600s. On Linux, `--enable-smart` opens the root-only controller ioctl nodes (`/dev/megaraid_sas_ioctl_node`, `/dev/tw??`, `/dev/aac?`) to the `disk` group, since `CAP_SYS_RAWIO` does not bypass file permissions. Two mechanisms, because one is not enough: a udev rule (`90-servermonitor-smart.rules`) covers the nodes udev actually manages, and a root `ExecStartPre=+` on `sm-agent.service` re-applies group and mode on every agent start. `/dev/megaraid_sas_ioctl_node` has no sysfs device behind it on many hosts (`udevadm info` reports "No such device"), so no udev rule can ever match it and it comes back root-owned at every boot — the `ExecStartPre` fixup is the only thing that keeps MegaRAID SMART alive across reboots. The agent auto-detects Broadcom storcli and Dell perccli at fixed trusted paths, refreshes controller data every 5m, directs vendor CLI logs to the system temp directory, uses exact controller/DID/slot enumeration to drive smartctl passthrough, and synthesizes temperature, media-error, and health metrics from the CLI when passthrough is refused. Hardware virtual disks emit `raid_degraded` with labels such as `c0/v0`, and probe failures are classified by opening the family's ioctl node directly (permission vs missing) rather than by parsing smartctl's prose, with the signature-matched family's failure outranking fallback families so a `cciss` miss cannot mask a `megaraid` permission wall.
